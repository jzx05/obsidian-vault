# 08 · RL 微调与工程配方

> [!abstract] 一句话
> VLA 里的 RL 通常是“少量微调”，不是从零训练：在 BC 策略上做 PPO/离线 RL，只动小模块，加 KL-to-base 和安全约束，防止策略崩坏和遗忘。

## 1. PPO

### 1.1 目标

重要性采样比率：

$$
r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\text{old}}(a_t\mid s_t)}
$$

Clipped objective：

$$
\mathcal{L}_{\text{PPO}}
=-\mathbb{E}\left[
\min\left(
r_t(\theta)\hat A_t,\;
\operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t
\right)
\right]
$$

总损失：

$$
\mathcal{L}
=\mathcal{L}_{\text{PPO}}
+\lambda_v\mathcal{L}_{V}
-\lambda_H H(\pi)
$$

- `L_V`：价值函数回归；
- `H(π)`：策略熵，鼓励探索；
- `ε`：clip 范围，常见 0.1–0.2。

### 1.2 直觉

- `A_t > 0`：提高该动作概率有好处，但 `r_t` 超过 `1+ε` 后不再奖励，防止更新过猛；
- `A_t < 0`：降低该动作概率有好处，但 `r_t` 低于 `1-ε` 后不再惩罚；
- `min` 是悲观的：只取两个估计中较小的那个，避免过度乐观。

### 1.3 GAE

$$
\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)
$$

$$
\hat A_t=\sum_{l=0}^{\infty}(\gamma\lambda)^l\delta_{t+l}
$$

- `λ=0`：接近 TD，偏差大方差小；
- `λ=1`：接近 Monte Carlo，无偏但方差大；
- 常用 `λ=0.95`。

## 2. VLA 适配要点

| 要点 | 做法 | 原因 |
|---|---|---|
| 只动小模块 | adapter / LoRA / 最后几层 | 保留 base policy 的动作分布 |
| KL-to-base | `KL(π_θ || π_base)` 惩罚 | 防止策略崩坏、遗忘 |
| 奖励设计 | 任务成功 + 安全 + 平滑 | 稀疏奖励难学，需 shaping |
| 数据 | 在线 rollout + 离线数据混合 | 真实机器人采样昂贵 |
| 安全 | barrier / 硬限幅 / 人工接管 | RL 探索可能危险 |
| 评估 | 多任务、多种子、闭环成功率 | 防止过拟合单一任务 |

**KL 正则**：

$$
\mathcal{L}_{\text{total}}
=\mathcal{L}_{\text{PPO}}
+\beta\,\operatorname{KL}(\pi_\theta\|\pi_{\text{base}})
+\lambda_v\mathcal{L}_V
-\lambda_H H(\pi)
$$

## 3. RL 微调的常见失败模式

- **策略崩坏**：学习率太大、KL 约束太弱、clip 太宽；
- **奖励黑客**：奖励设计与真实目标不一致；
- **探索不足**：熵系数太小、初始策略太确定；
- **遗忘**：没有 replay/蒸馏，旧任务成功率下降；
- **仿真到现实**：仿真奖励/动力学与真实不一致；
- **方差大**：GAE λ、batch size、种子数不够。

## 4. 工程上最常用的 6 套配方

| # | 场景 | 配方 |
|---|---|---|
| 1 | BC 基线 | MSE + action smooth |
| 2 | 多解任务 | GMM NLL + smooth |
| 3 | 高精度轨迹 | Diffusion ε loss + chunk + receding horizon |
| 4 | 高频部署 | Flow matching + chunk + smooth |
| 5 | 加入触觉不忘动作 | BC + replay + distill（KL/MSE）+ gating |
| 6 | RL 微调 | BC warm-start + PPO + KL-to-base + safety barrier |

**配方说明**：

1. **BC 基线**：先确认数据和 pipeline 没问题；MSE 最简单，收敛快。
2. **GMM**：多解明显、又不想上 diffusion 时的轻量选择；注意分量坍缩。
3. **Diffusion**：高精度、多模态轨迹；推理慢，用 DDIM/少步采样。
4. **Flow**：高频部署，采样步数少；注意速度场定义和路径设计。
5. **触觉/新模态**：回放旧数据 + 蒸馏 + adapter，防止遗忘。
6. **RL**：只做少量微调，KL-to-base 和安全约束是必须的。

## 5. 训练/调试检查清单

- [ ] 先跑通 BC 基线，确认动作能复现；
- [ ] 检查动作归一化、维度权重、夹爪处理；
- [ ] 看训练/验证损失，区分优化问题和数据问题；
- [ ] 多模态任务先看数据分布，再选损失；
- [ ] 加正则/barrier 后看任务成功率，不要只看损失；
- [ ] RL 微调监控 KL、熵、clip fraction、旧任务成功率；
- [ ] 评估用多种子、固定协议、置信区间。
